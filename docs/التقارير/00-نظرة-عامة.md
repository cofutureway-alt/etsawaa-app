## 1) ما هو المشروع

منصة سوق إلكتروني مصري متعدد البائعين (marketplace)، بواجهة عربية افتراضية وإنجليزية، مع RTL كامل، وعملة EGP مخزّنة بالقرش كأعداد صحيحة.

| العنصر | التقنية |
|---|---|
| الواجهة | React 19 + React Router 7 (framework mode، SSR) + TypeScript strict |
| التنسيق | Tailwind v4 + CSS custom properties (tokens من قاعدة البيانات) |
| الخلفية | Supabase: Postgres + Auth + Storage |
| الدفع | Kashier (بطاقات + محافظ إلكترونية) + الدفع عند الاستلام (COD) |
| البريد | Resend |
| الخطوط | Cairo variable self-hosted (صفر طلبات Google) |

## 4) المبادئ المعمارية المُنفَّذة فعلاً

1. **قاعدة البيانات مصدر الحقيقة.** الأسعار تُحسب داخل `fn_create_order`؛ العميل لا يرسل سعراً.
2. **المال بالقرش.** كل عمود مالي `*_piastres` كـ integer/bigint. لا floats.
3. **كل كتابة متعددة الصفوف = RPC ذرّي واحد.** `orders` ودفتر البائع لا يُكتبان من العميل.
4. **دفتر البائع هو المصدر.** `wallet_transactions` source of truth، والأرصدة تُحرَّك بـ trigger.
5. **RLS قبل الواجهة.** 74/74 جدول عليه RLS. منع الزر ليس أماناً — والكود يلتزم بهذا.
6. **الترجمة من قاعدة البيانات.** عناوين الموقع، التوكنات،صفحات المحتوى، قوالب الإيميل — كلها في `settings`/`static_pages`/`email_templates`.

## 5) الترتيب النسبي

| الطبقة | التقييم |
|---|---|
| SQL / RPC / RLS | **قوية جداً.** مكتوبة بعناية، ذرّية، مع idempotency وقيود CHECK. |
| نطاق الميزات | **واسع ومكتمل.** 8 مراحل و77+ مهمة موثّقة. |
| الواجهة والمكوّنات | **جيدة.** 19 مكوّن أساسي، ARIA، RTL، tokens. |
| الربط بين الطبقتين | **فيه ثقوب حقيقية.** جلسات، OAuth، فيشة checkout، فلاتر. |
| الأمن التشغيلي | **ضعيف.** كلمة سر أدمن في git، توكن إدارة على القرص. |
| ضمان الجودة | **يدوي بالكامل.** صفر CI، صفر تغطية آلية لـ SQL/RLS/الرايتس. |

## 6) الخلاصة في جملة

الكود **ليس مشروعاً وهمياً أو عرضاً تقنياً** — هو تنفيذ جدي لوثائق مفصّلة، وقاعدة البيانات فيه تتفوق على معيار المشاريع المشابهة. المشكلة ليست في نطاق الطموح ولا في مهارة التنفيذ، بل في **الطبقة الرابطة** (headers/cookies/filters/wiring) وفي **غياب بوابات آلية** تكشف هذه الثقوب قبل الإطلاق.
