# 03 — المصادقة ومنطقة الحساب

المصدر: `app/routes/auth/*`, `app/routes/account/*`, `app/lib/auth/guards.ts`, `app/features/auth/*`, `app/lib/phone.ts`, `app/lib/email/*`.

---

## 1) تدفق البريد + OTP

### التسجيل (`auth/register.tsx`)
1. التحقق بـ `registerSchema` (zod).
2. `client.auth.signUp({email, password, options:{data: {full_name, phone_e164, locale, terms_accepted_at}}})`.
3. الـ profile يُنشأ بـ trigger `on_auth_user_created`.
4. توجيه إلى `/{lang}/auth/verify?email=...`.

**مهم:** الكود السداسي **لا يُرسله كود التطبيق إطلاقاً**. هو بريد Supabase Auth الأصلي، مضبوط من لوحة تحكم Supabase. لا يوجد `supabase/config.toml` في الريبو.

### الإرسال والتبريد
- `OTP_RESEND_COOLDOWN_SECONDS = 60`; `resendSecondsLeft()` دالة نقية، مختبرة.
- التبريد الحقيقي هو Supabase فقط (`auth.resend`)؛ التطبيق يرصد `/rate|too many|wait/i`.

**عيب مؤكد:** `cooldownStart` لا يُعاد ضبطه بعد إعادة إرسال ناجحة → الزر يبقى مفتوحاً للأبد. وإعادة تحميل الصفحة تعيد العداد إلى 60.

### التحقق (`auth/verify.tsx`)
- مسار **الكود السداسي** (action): يرجّع `headers` صحيحاً (`:89,91,116,118`) → الجلسة تُحفظ. ✔
- مسار **لينك البريد** (loader، `:23`): `const { client } = ...` **بدون headers** → الجلسة تُفقد. ✘

### إكمال الملف (`auth/complete.tsx`) — لـ Google فقط
- `completeGoogleSchema` (هاتف + `terms === "on"`).
- يُحدّث `profiles.phone` فقط. **`terms` يُتحقق منه ولا يُخزَّن في أي مكان.**

### نسيت كلمة السر
- مسار الكود: `verifyOtp(recovery)` ثم `updateUser` في نفس الطلب — **يعمل**.
- مسار اللينك (`forgot.tsx:21`): يرمي headers → الجلسة تُفقد. ✘

## 2) Google OAuth — معطّل بالكامل

```ts
// auth/google.ts:14
const { client } = createSupabaseServerClient(request);
// :34
throw redirect(data.url, 302);                 // ← لا headers

// auth/google-callback.tsx:11
const { client } = createSupabaseServerClient(request);
// :23
await client.auth.exchangeCodeForSession(code); // ← لا headers
```

**سلسلة الفشل:**
1. `createServerClient` يفرض `flowType: "pkce"` (داخل `@supabase/ssr`).
2. `signInWithOAuth` يخزّن `code-verifier` عبر `setAll` → في `headers` المنفصل.
3. `headers` يُرمى → المتصفح لا يستلم الكوكي.
4. في الـ callback، `exchangeCodeForSession` يرمي `AuthPKCECodeVerifierMissingError`.
5. وحتى لو نجح، كوكي الجلسة يُرمى أيضاً.

**الإصلاح:** إضافة `headers` إلى الـ redirect في الموضعين — نحو 10 أسطر إجمالاً.

## 3) ميكانيكا كوكي الجلسة

`app/lib/supabase/server.ts:43-56` يمرر فقط:
```ts
{ cookies: { getAll, setAll } }
```
بلا `cookieOptions`.

قيم `@supabase/ssr` الافتراضية:
| الخاصية | القيمة |
|---|---|
| الاسم | `sb-<ref>-auth-token` (مقطّع عند 3180 بايت) |
| `path` | `/` |
| `sameSite` | `lax` |
| `httpOnly` | **false** — التوكنات مقروءة من JS |
| `maxAge` | 400 يوم |
| `secure` | **غير مضبوط** |

**لا يوجد `httpOnly` ولا `Secure` ولا `middleware`.** `root.tsx` ينشئ client لكنه لا ينادي `getUser` ولا يمرر شيئاً.

## 5) مخططات التحقق والتطبيع

### `app/lib/phone.ts`
- تحويل الأرقام العربية-الهندية.
- إزالة المسافات `-().`.
- إزالة `+20`/`0020`/`20` عند 12 رقماً.
- يجب `^01\d{9}$`، البادئات `010/011/012/015` فقط.
- يعيد `{e164: "+20XXXXXXXXXX", local: "01XXXXXXXXX"}`.

مطابق لقيد قاعدة البيانات `^\+[0-9]{10,15}$`. ✔

### `app/features/auth/schemas.ts`
- `passwordSchema`: 8–72 حرفاً (حد bcrypt)، حرف واحد (`A-Za-z` + عربي) + رقم.
- `loginSchema.identifier`: يحتوي `@` → بريد؛ وإلا هاتف.
- `otpCodeSchema`: `^\d{6}$`.
- `passwordStrengthScore` 0–4.

**عيب:** تغيير كلمة السر في `account/profile.tsx` **يتجاوز** `passwordSchema` — يفحص `length >= 8` فقط.

## 6) البريد (Resend)

`app/lib/email/server.ts`:
- Resend HTTPS فقط. لا node_emailer/SMTP.
- يقرأ `email_templates` بالـ key، يعدّل `{{var}}` باللغة، يرسل، ثم يسجّل كل محاولة في `email_logs`.
- بلا مفتاح → `{status:"failed", error:"RESEND_API_KEY missing"}`. لا يُزيّف النجاح. ✔

**القوالب المزروعة:** `welcome`, `order_confirmation`, `payment_success`, `payment_failed`, `order_shipped`, `order_delivered`, `order_cancelled`.

| القالب | يُرسل فعلاً؟ |
|---|---|
| `welcome` | نعم — عند التسجيل **وعند التحقق** (مكرر، وباسم فارغ `{{name}}`) |
| `order_confirmation` | نعم — COD فقط |
| `payment_success`/`payment_failed` | نعم — webhook Kashier |
| `order_shipped` | **لا** — اختبار يدوي فقط من صفحة القوالب |
| `order_delivered` | **لا** |
| `order_cancelled` | **لا** |

**الحالة المحلية:** `RESEND_API_KEY=` فارغ في `.env` → لا بريد حقيقي؛ كل محاولة تُسجَّل `failed`.

## 8) الخلاصة

مسار **البريد + كلمة السر + OTP السداسي** يعمل. مسار **Google** لا يعمل. مسار **لينك البريد** لا يحفظ جلسة. تثبيت الجلسة عبر التنقل ضعيف بسبب هدر `headers`.

البنية صحيحة والأنماط معروفة — الدليل أن `verify.tsx` action يستخدم النمط الصحيح في 4 مواضع. المشكلة تنفيذ جزئي، لا تصور خاطئ.
