## المستوى 1 — 🔴 معطّل وظيفياً

### 1.1 Google OAuth لا يعمل (سلسلة كاملة)

```
app/routes/auth/google.ts:14           const { client } = ...
app/routes/auth/google.ts:34           throw redirect(data.url, 302);      ← لا headers
app/routes/auth/google-callback.tsx:11 const { client } = ...
```

- `flowType: "pkce"` مفروض من `@supabase/ssr`.
- `signInWithOAuth` يكتب `code-verifier` في `headers` المنفصل.

- وحتى لو نجح، كوكي الجلسة يُرمى أيضاً.

**الإصلاح:** `throw redirect(url, { headers })` في الموضعين.

### 1.3 `/checkout` غير قابل للوصول من الواجهة

```
app/routes/cart.tsx:331-339
```

```tsx
<button type="button" disabled title={t("cart.checkoutNextPhase")}>
  {t("cart.checkout")}

```

لا يوجد أي `<Link to="/checkout">` في التطبيق بأكمله. الشراء ممكن فقط بكتابة الرابط.
**الأثر:** **لا يمكن لأي عميل إتمام طلب.** هذه أخطر فجوة وظيفية في المشروع.
**الإصلاح:** استبدل الزر بـ `<Link to={/${lang}/checkout}>`؛ اربط أيضاً من `CartDrawer` (المتوقع أن له زر Checkout).

### 1.4 كوبون الزائر يرجع HTTP 500


### 1.5 `event_discounts.max_discount_piastres` يعمل كأرضية سعر لا سقف خصم

```sql
-- 20261102000002_phase085_commissions.sql:271-273
v_unit := v_unit - trunc(v_unit * v_event_percent / 100);
if v_event_cap is not null and v_unit < v_event_cap then
  v_unit := v_event_cap;      -- يرفع السعر
end if;
```
```ts
// app/features/checkout/pricing.server.ts:152-153 — نفس الخطأ
```

**مثال:** منتج 6000 قرش، خصم فعالية 50%، سقف 5000 → السعر الصحيح 3000؛ الكود يعطيه 5000.
**الأثر:** العميل يدفع أكثر مما يجب في الفعاليات. خطأ مالي في مكانين.
**الإصلاح:** قيّد مبلغ الخصم لا السعر:
```sql
v_disc := trunc(v_unit * v_event_percent / 100);
if v_event_cap is not null and v_disc > v_event_cap then v_disc := v_event_cap; end if;
v_unit := v_unit - v_disc;
```

## المستوى 2 — 🟠 عيوب تؤثر على الاستخدام اليومي

### 2.1 تدوير التوكن يُفقد في معظم الـ loaders

`app/lib/supabase/server.ts` يعيد `{client, headers}`، لكن ~105 ملف يفعلون `const { client } = ...`.

المواضع الصحيحة (5 فقط): `login.tsx:79`, `verify.tsx:89,91,116,118`, `forgot.tsx:82`, `logout.ts`.

**الأثر:** `refresh_token` يدور لكن الكوكي الجديد لم يُرسل → خروج عشوائي. هذا هو H-05، **ولا يزال مفتوحاً** تقنياً رغم إقفال المرحلة.

### 2.2 كوكيز الجلسة بلا `httpOnly` وبلا `Secure`

`app/lib/supabase/server.ts:43-56` يمرر فقط `cookies: {getAll, setAll}`.
الافتراضيات من `@supabase/ssr`: `httpOnly: false`, `sameSite: "lax"`, `maxAge: 400 يوم`, **`secure` غير مضبوط**.

**الأثر:** XSS يستطيع سرقة التوكن؛ الكوكي ينتقل عبر HTTP.

### 2.3 صلاحيات `staff` شكلية

`app/lib/permissions.ts:18` — `can()` **غير مستخدم في أي ملف**.
`canAccessPanel` يمنح admin|staff وصولاً كاملاً للوحة.
`has_permission()` مستخدمة في 6 مواضع فقط؛ الباقي `is_admin()`.

**الأثر:** staff يرى كل السايدبار، وتُرفض كتاباته، فتصبح التجربة مربكة. مصفوفة `/admin/roles` بلا أثر.
**مخالفة صريحة** لبوابة G2 في `phase-07`.

### 2.4 `profiles.email` لا يُزامَن بعد تغيير البريد

تحديث `auth.users.email` عبر `updateUser`، ولا trigger يحدّث `profiles.email`.
**الأثر:** الدخول بالهاتف عبر `fn_resolve_email_from_phone` يعيد البريد القديم → دخول يفشل بعد التغيير.

### 2.5 `wishedIds` لا يُمرَّر إلى `<Listing>`

`app/features/storefront/server-listing.ts:108` يحسبه، و4 راوتس (`products`, `category`, `search`, `brand`) لا تمرره.
**الأثر:** قلب المفضلة فارغ دائماً في صفحات القوائم رغم أن المستخدم أضاف منتجات.
**استعلام ميت** لكل صفحة قائمة.

### 2.6 فلاتر الخصائص غائبة في `/products`, `/search`, `/brand`

`server-listing.ts:63` → `defs = []` إن لم يكن هناك قسم ثابت. وتجاهل معامل `cat` في URL.
**الأثر:** `fn_search_products` يعيد فاسيت الخصائص، والواجهة ترميها. نصف نظام الفلترة معطّل.

### 2.7 مصغرات معرض المنتج لا تعمل

`app/routes/product.tsx:262` → `onSelect={() => undefined}`.
الصورة مشتقة من المتغير المختار فقط (`product.tsx:164`).
**ملاحظة تحقق:** ليس خطأ وقت تشغيل — ببساطة لا استجابة.

### 2.8 `fn_media_usage` فيه `where false` placeholder

`20261031000001_phase02_media_rpc.sql` — فرع بلا أثر، والمسح لا يغطي المنتجات/المنشورات/البانرات/الأفاتارات.
**الأثر:** حذف صورة مستخدمة في منتج قد يمرّ → صورة مكسورة في المتجر.

### 2.9 `max_dimensions_px` غير مطبَّق

مخزَّن في `settings.media` وقابل للتعديل في `/admin/media-settings` — ولا يفحصه `validateUpload` ولا دالة Edge.

### 2.10 إعدادات المستندات ميتة

`/admin/document-settings` يكتب `settings['documents']`، و`order-print.tsx` + `documents.server.ts` لا يقرآن أي إعداد.
**الأثر:** المستخدم يعدّل النسخ/الورق/الشعار ولا شيء يتغير.
**تصحيح دقيق:** الصفحة نفسها تقرأ القيمة (`document-settings.tsx:28`) — لكن لا مستهلك طباعة.

### 2.13 إيميلات دورة حياة الطلب لا تُرسل

`order_shipped`, `order_delivered`, `order_cancelled` موجودة في القوالب — `sendEmail` لا يُنادى بها على أي حدث طلب.

### 2.14 إلغاء طلب مدفوع لا يعيد المال

`fn_cancel_order` يقبل طلبات `paid`، يضبط `status='cancelled'` ويترك `payment_status='paid'`.
لا استرداد ولا void في Kashier.

### 2.15 `store_members` لا يمنح أي صلاحية

`own_vendor_id()` = `vendors.owner_id`. لا جدول آخر يستعلم `store_members`.
**الأثر:** دعوة عضو فريق للبائع (owner/staff) لا تعطيه شيئاً. مخالفة `ARCHITECTURE §4`.

### 2.16 `fn_confirm_payment` لا يعيد فحص طريقة الدفع أو الحالة

يقبل webhook لطلب ملغى أو غير `kashier`. وإعادة استخدام `provider_ref` فاشل ثم ناجح تصطدم بـ UNIQUE → 500.

## ما لا أوصي بتغييره

- **`fn_create_order` ككل.** ذرّية، تقفل الصفوف، ترفض أسعار العميل، وتتعامل مع 3 أنواع كوبونات بتوزيع pro-rata. أعقد قطعة في المشروع وأفضلها تنفيذاً.
- **نموذج المتغيرات.** ديكارتي مع tombstones لا تُبعث و`option_key` فريد جزئي. صحيح.
- **دفتر المحفظة.** `fn_post_transaction` idempotent + trigger يحرّك الأرصدة + قيد «السالب يتطلب سبباً». تصميم سليم.
- **عزل مستندات البائع.** `fn_vendor_order_snapshot` يعيد أعمدة آمنة فقط. صحيح.
- **نظام التوكنات.** DB → CSS → Tailwind → كل مكوّن، مع فحص WCAG في الاختبارات. متكامل.
- **نظام الـ staging.** 14/14 تحقق، عزل RLS، دفتر رفض. جيد.
