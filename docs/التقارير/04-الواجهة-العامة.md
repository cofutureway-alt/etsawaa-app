المصدر: `app/routes/{home,products,category,search,product,store,vendors,brands,brand,compare,blog,...}.tsx` + `app/features/{storefront,products,discovery}/*` + `app/components/catalog/*`.

## 1) محرّك القوائم — واحد لأربع واجهات

`app/features/storefront/server-listing.ts`:

```
resolveScope(categorySlug?, brandSlug?)
   ├─ قسم بـ slug من v_storefront_categories + سلسلة الآباء من path
   ├─ ماركة بـ slug
   └─ v_storefront_facet_defs مرشّحة على شجرة القسم
          ⚠️ إن لم يُحلّ قسم → defs = []   (سطر 63)

loadListing()
   ├─ parseListingState(url)         ← حالة URL
   ├─ searchProducts(RPC)            ← fn_search_products
   └─ wishedIds (استعلام المفضلة)
```

**RPC:** `fn_search_products(p_q, p_category, p_brand, p_attrs, price_min/max, rating, in_stock, sort, page, per_page)` في `20261031000005_phase04_storefront.sql:925`. يعيد `{total, page, per_page, items, facets{brands,categories,attributes}}`.

### البحث النصي (FTS)
```sql
fn_tsv_match(id, q) → products.search_tsv @@ websearch_to_tsquery('arabic', q)
```
`search_tsv` عمود مولَّد من `name_ar || ' ' || name_en`، عليه فهرس GIN.

احتياطيات بالتوالي:
1. `ar_norm(name_ar) LIKE '%norm%'` — يطوي الهمزة والألف والتاء المربوطة والألف المقصورة والتشكيل.
2. `name_en ILIKE '%q%'`.
3. `pg_trgm` على `name_ar % q` و`name_en % q`.

**قيد:** البحث في **أسماء المنتجات فقط** — لا الوصف ولا الماركة ولا اسم المتجر.

### الترتيب
| الخيار | التعبير |
|---|---|
| `newest` | `is_featured desc, published_at desc nulls last` |
| `price_asc/desc` | السعر **بعد خصم الفعالية** |
| `rating` | `rating_count desc, rating_avg desc` |

لا يوجد ترتيب بالصلة (relevance) رغم وجود FTS.

### الفاسيت
- **الماركات:** الأساس ناقص فلتر الماركة + شرط الخصائص، **يتجاهل** `q`/السعر/التقييم/المخزون.
- **الأقسام:** **بلا أي ترشيح** — عدّ على كل المنتجات القابلة للعرض.
- **الخصائص:** الأساس ناقص فلتر الخصائص + الماركة فقط.

الخيارات الصفرية تظهر (الانضمام على `v_storefront_facet_options`).

### حالة URL
- مفاتيح الخصائص بكود بشري، معرفات خيارات مفصولة بفواصل، تُفحص `^[0-9a-f-]{36}$`، بحد 20 لكل خاصية.
- `pmin/pmax` بالجنيه → تحويل إلى قرش.
- `page` بين 1 و500.

### الواجهات الأربع
| الراوت | الاستدعاء | النطاق المثبّت |
|---|---|---|
| `products.tsx` | `loadListing` | لا شيء |
| `category.tsx` | `loadListing({fixedCategorySlug})` | قسم |
| `search.tsx` | `loadListing({forceQ})` | لا شيء |
| `brand.tsx` | `loadListing({fixedBrandSlug})` | ماركة |

## 2) صفحة المنتج

المصدر `getProductPage` في `app/features/storefront/api.ts:426`:
1. `v_storefront_products` بـ `slug_ar OR slug_en`.
2. صف `products` الأساسي (وصف، specs، fragile، shipping_mode، وزن، نافذة الخصم، brand).
3. **إعادة فحص** `status === 'approved' && !deleted_at`.
4. قراءات متوازية: `product_media`, `variants`, `product_attribute_values` + `attribute_defs`, `v_storefront_reviews` (منشورة، 50), `brands`.

### المتغيرات
- المحاور من `option_ids` → `attribute_options` → `attribute_defs`.
- `?v=` = `option_key` (معرفات الخيارات مرتبة مفصولة بفاصلة).
- `VariantSelector` يعطّل الخيارات التي لا متغير متاح لها مع الاختيارات الأخرى.

### السعر
- الصفحة تعرض **سعر المتغير المختار**، لا `MIN(variant.price)`.
- خصم المتغير يُطبَّق فقط إذا كان `sale_starts_at` مضبوطاً و`now ∈ [start,end]`.
- خصم الفعالية يُعاد حسابه في JS.

### المعرض
`Gallery.tsx` — صورة رئيسية + مصغرات. الصورة المختارة:
```ts
// product.tsx:164
selected?.image_path ?? images[0]?.path
```
والمصغرات:
```tsx
// product.tsx:262
onSelect={() => undefined}
```

**النتيجة الفعلية (بعد التحقق العدائي):** الضغط على مصغرة **لا يفعل شيئاً**، لأن الصورة مشتقة من المتغير المختار لا من `onSelect`. تغيير المتغير فقط يغيّر الصورة. لا خطأ وقت التشغيل — لا استجابة.

### المراجعات
- المتوسط من البطاقة (`rating_avg`, `rating_count`).
- توزيع النجوم محسوب على **الـ 50 المحمّلة فقط**، لا على الإجمالي.
- لا نموذج مراجعة على الصفحة — الكتابة في `/account/reviews`.

### JSON-LD (Product)
`name`, `description` (500 حرف), أول 4 صور, `Brand`, `sku` للمتغير المختار, `Offer` واحد (EGP، السعر بعد خصم الفعالية، `InStock`/`OutOfStock`, `seller: Organization`), `aggregateRating` عند وجوده.

**ضعف SEO:** لا `review` array، لا `priceValidUntil`، لا `itemCondition`. السعر يتغير حسب `?v=` — وقد يربك الزواحف.

## 4) سلوك الزائر

### السلة
- زائر: `localStorage["etsawaa.cart.v1"]` — `{variant_id, product_id, qty}` فقط.
- بيانات العرض تُحلّ بطلب `POST /api/cart {intent:"peek"}` — anon، بحد `min(requested, stock, 99)`.
- مسجّل: DB عبر RPCs `fn_cart_*`.
- الدمج عند الدخول: `greatest(existing, local)` مُقيَّد بالمخزون، ثم مسح localStorage.

**تناقض:** `peek` يحسب سعر الخصم فقط، **لا خصم الفعالية** — بينما checkout يطبّقه. سعر السلة يختلف عن سعر الطلب.

### المفضلة
- DB فقط. زائر → 401 → تُخزَّن في `etsawaa.wish.pending.v1` + تحويل للدخول، ثم تُدمج.
- `loadListing` يجلب `wishedIds`... **ولا راوت يمرره إلى `<Listing>`**. النتيجة: القلوب فارغة دائماً في صفحات القوائم.

### آخر المشاهدات
- زائر: `etsawaa.recent.v1` بسقف 20.
- مسجّل: DB عبر `fn_record_view`، آخر 20.
- `home.tsx:349` يمرر `viewerId={null}` **دائماً** → المسجّل يرى شريط الزائر على الرئيسية.

### المقارنة
- التخزين: `etsawaa.compare.v1`، بحد 2.
- الصفحة `URL` فقط: `/compare?ids=uuid,uuid`، تُفحص بـ regex.
- يعرض الخصائص المشتركة + السعر/التقييم/البائع.

## 7) ملاحظة على عيب كان مرشَّحاً وتم رفضه

**`process.env.SUPABASE_URL` في blog:** التحقق أثبت أن Vite يستبدل `process.env` بـ `{}` في بناء العميل — لا `ReferenceError`. العَرَض الحقيقي أضيق: `supabaseUrl = ""` على العميل → روابط صور المقالات مكسورة عند التنقل SPA.

هذا يوضح قيمة مرحلة التحقق العدائي: ادعاء كان سيبدو خطيراً في تقرير غير مُتحقَّق منه.
