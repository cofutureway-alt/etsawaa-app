# 05 — لوحة البائع ولوحة الأدمن

المصدر: `app/routes/vendor/*` (11 ملف), `app/routes/admin/*` (33 ملف), `app/layouts/{vendor,admin}.tsx`, `app/components/layout/{PanelShell,SidebarNav}.tsx`.

## 1) نموذج التنقل

`PanelShell` — سايدبار داكن لاصق (`--sidebar-w` 240px / `--sidebar-w-collapsed` 64px)، طي، شريط علوي (عنوان/وصف/أزرار)، محتوى 1200px، `<meta robots noindex,nofollow>`.

`SidebarNav` يدعم `SidebarItem {to,label,end,icon,badge?,disabled?,phase?}`. **`badge`, `disabled`, `phase` غير مستخدمة في أي لوحة** — قدرة ميتة.

### سايدبار البائع
- المتجر: dashboard, products, products/new
- إعدادات المتجر: store, media
- الحساب: orders, wallet, reports, penalties, profile

+ شريط علوي بمؤشر التحقق ومبدّل اللغة. بانرات مستمرة حسب الحالة: `pending` · `rejected` (+إعادة إرسال) · `suspended` · `grace_expired` · عدّاد grace.

### سايدبار الأدمن — 7 مجموعات
| المجموعة | العناصر |
|---|---|
| Operations | dashboard, orders, refunds, vendors, products, shipping, withdrawals |
| Marketing | coupons, ads, events, banners |
| Catalog | data-import, categories, brands, tags, attributes, reviews |
| Trust | penalties, levels |
| Reports | reports, logs |
| Content | blog, pages |
| Platform | users, roles, customers, media, zones, settings/sections, document-settings, email-templates, settings, profile |

`media-settings` راوت موجود، **غائب من السايدبار** — يُوصل إليه من صفحة الإعدادات فقط.

## 2) بوابة الصلاحيات

```ts
// app/lib/auth/guards.ts:95
canAccessPanel(role, "admin")  → role === "admin" || role === "staff"
canAccessPanel(role, "vendor") → role === "vendor" || role === "admin"
canAccessPanel(role, "account") → true
```

**لا ترشيح للسايدبار، ولا بوابة لكل صفحة، ولا بوابة لكل فعل.**

`can()` و`DEFAULT_STAFF_PERMISSIONS` في `app/lib/permissions.ts` **غير مستخدمين خارج الاختبارات** (تحقق مؤكد).

### النتيجة العملية
- الـ `staff` يمرّ من البوابة ويرى **كل** السايدبار.
- لكن معظم الجداول/الـ RPC مقيّدة بـ `is_admin()`.
- `has_permission()` يُستخدم فقط في: `users.manage`, `users.read`, `settings.read/write`, `products.review`, `vendors.review`, `vendors.verify`.
- فـ staff يصل إلى صفحات بقوائم فارغة أو يرفض عليه الكتابة.
- مصفوفة `/admin/roles` (بعد برنامج `fn_admin_set_role_permissions`) **تجملية** فعلياً.

**مخالفة صريحة** لبوابة G2 في `phase-07` PLAN: «staff بصلاحيات محدودة يرى فقط المسارات والعمليات المسموحة».

## 4) معالج تسجيل البائع (`vendor/onboarding.tsx`)

5 خطوات:
1. **المتجر** — اسم ar/en، وصف، slug تلقائي، أقسام (1–10)، شعار + بانر عبر `MediaPickerDialog`.
2. **البيانات** — الاسم، الهاتف، محافظة + منطقة متتالية، عنوان، 5 شبكات اجتماعية.
3. **التحقق (اختياري)** — رفع مستندات حسب `config.required_documents` (`id_front`, `id_back`, `commercial_register`, `tax_card`, `residence`).
4. **الشروط** — نص من الإعدادات + checkbox + توقيع مكتوب (≥4).
5. **المراجعة** — كتل للقراءة فقط + قفزات تعديل.

RPCs: `fn_vendor_config`, `fn_vendor_autosave` (debounce 1200ms)، `fn_vendor_onboard`.

**مفيد:** `terms_version`, `terms_accepted_at`, `terms_signature` **مخزَّنة فعلاً** في `vendors` (تحقق: `phase03_vendor_core.sql:77,491,543`). مخالف لتوقعي الأولي.

**عيب مؤكد:** `DocumentUploader.upload` (`onboarding.tsx:323-345`) يحل الوعد على `onerror` ولا يفحص `xhr.status` → يمكن كتابة صف `vendor_documents` لملف فشل رفعه.

## 5) معالج المنتج

5 خطوات: أساسيات → تصنيف/ميديا → تسعير → خصائص+متغيرات → شحن/مراجعة.

### القالب
`loadTemplate` = `attribute_defs` المملوكة للورقة + المربوطة عبر `category_attributes`. الأنواع: `text|number|bool|enum|color`.

### مصفوفة المتغيرات
- المحاور = خصائص `is_variant_axis`.
- التوليد: `fn_generate_variants(p_product_id, p_axes, p_defaults)` → `{inserted, removed, skipped[]}`.
- المفاتيح المدفونة (tombstones) لا تُبعث، وتُعرض كاستعادة عبر `fn_restore_variants`.
- التحرير: SKU، سعر، خصم، مخزون، صورة، `is_active` لكل صف.
- الحفظ: `fn_save_variants`.

### الحفظ التلقائي
debounce 1200ms → `intent=save` → `fn_save_product`. كشف تعارض تبويبين عبر `baseUpdatedAt` مقابل `products.updated_at`.

### الإرسال
التأكد من متغير حي واحد على الأقل ثم `fn_submit_product`.

### عيوب

| 1 | `form.price` يُهيَّأ `""` حتى عندما تحمل المتغيرات أسعاراً → حقل السعر فارغ عند التعديل |

## 7) ما يعمل بجدية

لوحة الأدمن **ليست هيكلاً فارغاً**. `refunds`, `order-detail`, `vendors_.$id.edit`, `catalog/attributes`, `catalog/categories`, `email-templates`, `zones`, `penalties`, `levels` كلها RPC حقيقية مع تدقيق. معالج المنتج بمصفوفة المتغيرات والحفظ التلقائي هو الأكثر تعقيداً في المشروع وهو يعمل.

المشكلة في اللوحات ليست الغياب — بل **التفاصيل**: إعدادات لا تُقرأ، صلاحيات لا تُفرَض، أعمدة خاطئة، ومسارات مكررة.
