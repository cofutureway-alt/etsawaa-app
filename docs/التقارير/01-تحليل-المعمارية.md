# 01 — تحليل المعمارية والراوتينج

المصدر: `app/root.tsx`, `app/routes.ts`, `app/layouts/*`, `app/lib/*`, `react-router.config.ts`, `vite.config.ts`.

---

## 1) SSR مقابل SPA

```ts
// react-router.config.ts
export default { appDirectory: "app", ssr: true } satisfies Config;
```

- **كل شيء SSR.** لا يوجد `clientLoader` واحد في التطبيق (عدد = 0)، ولا راوت بـ `ssr: false`، ولا `prerender`.
- نصف الـ SPA هو التنقل بعد الهايدريشن فقط: `<Links/>` + `<Scripts/>` + `<ScrollRestoration/>` في الجذر.
- أثناء التنقل على العميل، React Router **يستدعي loaders السيرفر من جديد** — كل صفحة لوحة = رحلة شبكة كاملة.
- تقسيم الكود: فقط `CartDrawer` و`CompareBar` محمّلان بـ `lazy()` داخل `app/layouts/public.tsx:32-33`.

**انحراف عن الوثيقة:** `ARCHITECTURE §1.4` و`AGENT §1.14` يقولان "SSR للعامة، SPA للوحات". غير متنفّذ. اللوحات SSR كاملة.

  │   ├─ checkout, order/:number, order/:number/track
  │   └─ account (id: account-public-frameshell)
  │       └─ layouts/account.tsx (pathless)  → 11 صفحة حساب
  ├─ vendor/onboarding               ← خارج لوحة البائع (تدفق مركّز)
  ├─ layouts/vendor.tsx              → 11 صفحة
  ├─ layouts/admin.tsx               → 33 صفحة
  ├─ ui                              → معرض مكوّنات داخلي (noindex)
  └─ api/{notifications,areas}

**ملاحظة معمارية:** راوت الطباعة جذرُه الجذر (لا `:lang`) لأن الـ loader يعيد `Response` خام، وloaders المتداخلة تغذي layouts فقط. قرار صحيح ومُوثَّق في تعليق.

## 3) اللاي أوتس والحماية

| اللاي أوت | الحارس في loader | يقدّم |

## 4) الجلسة والمصادقة في loaders

`app/lib/supabase/server.ts` يعيد `{ client, headers }`:
- `getAll` يقرأ كوكي الطلب.
- `setAll` يُلحق `Set-Cookie` في كائن `headers` منفصل.

**المشكلة الجوهرية:** `headers` ذلك يُرجَع من الـ loader — أي `redirect(url, {headers})` أو `data(x, {headers})`. ومعظم الـ loaders تفعل `const { client } = createSupabaseServerClient(request)` وتتجاهل `headers`.

هذا يعني أن **أي تدوير refresh-token يحدث أثناء `getUser()` يُفقد**. المواضع التي ترسله صحيحاً هي 5 فقط: `login.tsx:79`, `verify.tsx:89,91,116,118`, `forgot.tsx:82`, `logout.ts`.

`getViewer` في `app/lib/auth/guards.ts:45-67`:
```ts
if (error) {
  if (isAuthSessionMissingError(error)) return { viewer: null };
  if (error instanceof AuthApiError && [400,401,403].includes(error.status))
    return { viewer: null };
  return { viewer: null, sessionStale: true };   // شبكة/5xx — لا تخرج المستخدم
}
```
المنطق سليم. لكن `requirePanelAccess` يضيف `&stale=1` إلى راوت الدخول، و`login.tsx:111` **لا يقرأ `stale`** — لا يوجد نسخ i18n له أصلاً. المستخدم يدخل إلى تسجيل الدخول بلا تفسير.

## 5) اللغة وRTL

- `LOCALES = ["ar","en"]`, `DEFAULT_LOCALE = "ar"`.
- الجذر يشتق اللغة من أول قطعة في المسار: `isLocale(segment) ? segment : "ar"`.
- `<html lang dir>` يُرندر على السيرفر من بيانات الـ loader — الإنجليزية LTR من أول بايت.
- `switchLocalePath(pathname, search, hash, next)` يستبدل القطعة الأولى ويحفظ query وhash.
- RTL: خصائص منطقية (`ms/me/ps/pe/start/end`) + `.mirr` (`scaleX(-1)`) + `.num` (`unicode-bidi: isolate` + `direction: inherit`).
- `requireLang` يرمي `404 Response` لأي لغة غير `ar|en`.

**نقطة:** صفحات الخطأ في الجذر مثبّتة على `<html lang="ar" dir="rtl">` حتى في `/en` (`root.tsx:108,176`). كذلك روابط `RouteErrorBoundary`.

## 6) SEO

| العنصر | الحالة |
|---|---|
| Meta لكل صفحة | `publicMeta` في `app/lib/seo.ts:27-54` — title, description, robots, canonical, hreflang ar/en/x-default, OG, Twitter |
| JSON-LD | Organization + WebSite/SearchAction (home) · Product/Offer/Brand/AggregateRating (product) · BreadcrumbList · BlogPosting · ItemList (products/category) |
| sitemap.xml | ديناميكي، صفحات + أقسام + منتجات (5000) + متاجر + ماركات + مقالات. `Cache-Control: max-age=3600` |
| robots.txt | يحجب admin/vendor/account/auth/ui للغتين + مؤشر sitemap |
| rss.xml | RSS 2.0, 30 مقال, `?lang=ar\|en` |

**عيوب مؤكدة:**
1. `seo.ts:41` — `x-default` يشير إلى اللغة الأخرى بدل `ar`، بينما `sitemap[.xml].ts:71` يستخدم `ar`. تناقض بين المكانين.
2. `root.tsx:59-60` يكتب `<title>` و`<meta description>` يدوياً **بجانب** `<Meta/>` → عنوانان ووصفان في الصفحات المتداخلة.
3. `products.tsx:50` — `ItemList.url` قيمة slug نسبية لا URL مطلق.
4. `rss[.xml].ts` يستخدم `client!` بلا فحص null → تفشل عند غياب الإعداد.
5. robots.txt لا تحجب `/checkout`, `/order`, `/compare`, `/search`, `/vendor/onboarding` (تعتمد على `meta noindex` فقط).

## 7) البيئة والإعدادات

`.env.example` يعلن: `SUPABASE_URL`, `SUPABASE_ANON_KEY`, `SUPABASE_SERVICE_ROLE_KEY`, `RESEND_API_KEY`, `EMAIL_FROM`, `SITE_URL`, `KASHIER_*`.

**ناقص في `.env.example` بينما تستخدمه السكربتات:** `SUPABASE_ACCESS_TOKEN`, `SUPABASE_PROJECT_REF`, `PORT`.

`vite.config.ts`:
- `loadEnv(mode, cwd, "")` ينسخ كل شيء إلى `process.env` في التطوير.
- `define` يربط `VITE_SUPABASE_URL/ANON_KEY` من `VITE_*` أو `SUPABASE_*`.
- `envPrefix` الافتراضي `VITE_` فقط → `SUPABASE_SERVICE_ROLE_KEY` لا يُبنى للمتصفح. قرار صحيح وصريح.

**استخدام `service_role` في 8 مواضع داخل RR** (خلافاً لـ ARCHITECTURE §4 "Edge/RPC فقط"):
`api/webhooks/kashier.ts:16`, `checkout.tsx:196`, `auth/register.tsx:93`, `auth/verify.tsx:100,107`, `blog.$slug.tsx:78-79`, `sell.tsx:38`, `admin/email-templates.tsx:117`, `api/admin-import-rejects.ts:18`.
