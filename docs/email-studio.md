# استوديو الإيميلات

من لوحة الإدارة ← الإعدادات ← قوالب البريد الإلكتروني، ابحث عن الرسالة أو اختر جمهورها. تبويب العربية والإنجليزية يحدد النسخة التي تعدّلها؛ لغة لوحة الإدارة لا تحدد لغة المستلمين.

عدّل عنوان البريد والنص المختصر والعنوان الداخلي والمحتوى والتفاصيل والزر والملاحظة. اترك سطرًا فارغًا بين الفقرات. لإدراج معلومة تتغير تلقائيًا، ضع المؤشر في الحقل ثم اضغط اسم المعلومة. اللوجو والألوان والتنسيق ثابتة للحفاظ على الهوية.

- **حفظ مسودة:** يحفظ عملك دون التأثير على الرسائل الفعلية.
- **نشر التعديلات:** ينشر النسختين بعد التحقق منهما، ويضيف إصدارًا يمكن استرجاعه.
- **إرسال تجربة:** يرسل المسودة الظاهرة، بما فيها التعديلات غير المحفوظة، باللغة المختارة وببيانات توضيحية. لا ينشرها للعملاء.
- **استرجاع إصدار:** ينشر محتوى الإصدار المختار كإصدار جديد. النسخ السابقة تبقى محفوظة.
- **إيقاف الإرسال:** يوقف الرسالة الاختيارية. رسائل الأمان الأساسية تظل مفعلة.

إذا عدّل مسؤول آخر الرسالة، لن يُكتب فوق تعديله: انسخ تعديلاتك ثم حدّث الصفحة. تغيير القالب أو مغادرة الصفحة مع تعديل غير محفوظ يُظهر تنبيهًا.

## لغة الرسائل

لغة الإجراء المباشر تتبع الصفحة المستخدمة. اللغة تُحفظ للحساب عند الاستخدام وتسجيل الدخول، وتقرأها رسائل الشحن والدفع اللاحقة والإشعارات عند تجهيز الإرسال. روابط الموقع داخل الرسالة تتبع اللغة نفسها. لغة رد الدعم تتبع الحساب أو لغة المحادثة المحفوظة للزائر، وليس لغة الموظف الذي يرد.

النص الذي كتبه شخص بنفسه، مثل رسالة الدعم أو سبب الإلغاء، يُعرض كما كُتب؛ لا تُترجم بيانات الأشخاص آليًا. النصوص النظامية تتوفر باللغتين.

## التشغيل والتحقق

- `npm run verify`: فحص الأنواع والـlint والاختبارات والبناء.
- `node --import tsx scripts/email-studio-artifacts.ts`: إنشاء ترحيل الكتالوج والمعاينات من المصدر المعتمد. الترحيل لا يستبدل تعديلات الاستوديو عند إعادة تشغيله.
- `node scripts/qa-email-studio.mjs`: اختبار المحرر الحقيقي في بيئة معزولة، مع إجراءات داخل الذاكرة لا ترسل بريدًا ولا تعدّل بيانات الإنتاج.
- الترحيلان `20261122000074` و`20261122000075` يضيفان المحتوى المنظم والمسودات والإصدارات والطابور المشفّر والكتالوج. HTML المتوافق مع الإصدار السابق محفوظ أيضًا، ونسخة القوالب الأصلية مؤرشفة قبل الترقية.
- `deploy/email-studio-release.py` يبني نسخة مرشحة، ويحفظ نسخة من بيانات القوالب والدوال وصورة التطبيق وإعدادات Auth قبل النشر. لا يرسل رسائل تجريبية؛ يفحص SMTP بتسجيل الدخول وNOOP فقط.

رسائل الأمان تستخدم Send Email Hook موقّعًا. الطلب يحفظ مهمة مشفّرة بـAES-256-GCM ثم يجيب سريعًا لتفادي مهلة Auth البالغة خمس ثوانٍ. العامل يرسل كل ثانية، ويعيد المحاولة حتى خمس مرات، ويحذف المحتوى المشفّر بعد النجاح أو انتهاء الصلاحية. معرف الطلب يمنع إعادة جدولة الرسالة نفسها. بيانات القالب والأكواد والروابط السرية لا تدخل السجلات.

`AUTH_EMAIL_HOOK_SECRET` و`AUTH_EMAIL_ENCRYPTION_KEY` أسرار خاصة بالسيرفر، والثاني مفتاح base64 بطول 32 بايت ويجب الاحتفاظ به عند تدوير سر التوقيع. `AUTH_EMAIL_OTP_EXP` يطابق إعداد Auth؛ التحديث لا يغير مدة الصلاحية. لمراقبة التسليم، راجع `email_logs` وحالات `auth_email_deliveries` دون فك المحتوى المشفّر.

## الرجوع

نسخة السيرفر تحت `/opt/etsawaa/backups/email-studio-<timestamp>` وصورة التطبيق السابقة باسم `etsawaa-app:before-email-studio-<timestamp>`.

للرجوع الكامل: أعد إعدادَي Supabase من `supabase-compose-before.yml` و`supabase-env-before` وأعد تشغيل خدمة Auth وحدها، ثم أعد صورة التطبيق وملفات runtime وإعداداته من النسخة المحفوظة. `templates-before.json` و`functions-before.sql` يحفظان محتوى القوالب والدوال الأصلية لإعادتها دون استعادة قاعدة الموقع كلها أو التأثير على طلبات جديدة. عند وجود رسائل أمان معلقة، يجب إنهاء تسليمها أو التعامل معها قبل إيقاف العامل.
